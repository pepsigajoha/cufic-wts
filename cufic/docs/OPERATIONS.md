# 대회 당일 운영 순서 (OPERATIONS)

> ⚠ **초안 — 리허설 전.** 이 문서는 아직 **실제 리허설로 검증되지 않았다.** 순서·타이밍은
> 대회 전 초기화 리허설(→ [ROADMAP](ROADMAP.md) "실제 수업 전 필수")에서 확인·수정해야 한다.

관련: 게임 규칙 [GAME_RULES.md](GAME_RULES.md) · **관리자 화면 조작 [MANUAL_ADMIN.md](MANUAL_ADMIN.md)** · 데이터 만들기 [MANUAL_CONTENT.md](MANUAL_CONTENT.md) · 화면 [SCREENS.md](SCREENS.md).

## A. 사전 준비 (대회 전날/직전)

1. **Supabase 프로젝트 활성 확인 (전날 필수)** — 무료 플랜은 약 1주 무요청 시 DB를 **일시정지**한다.
   정지 상태면 학생·관리자 화면이 전부 "fetch failed"로 먹통이 되므로, 전날 반드시 확인한다.
   - [Supabase 대시보드](https://supabase.com/dashboard/project/zhwidhvoxcoljffvqhol)에서
     프로젝트 상태가 **Active**(초록)인지 본다. `Paused`면 **[Resume project]**로 깨우고,
     1~2분 뒤 학생 화면(`/`)이 정상으로 뜨는지 확인.
   - 평소엔 GitHub Actions **Keep-Alive**(`.github/workflows/keepalive.yml`)가 매일 자동 핑으로
     재우지 않게 막는다. **단, 저장소 시크릿(`SUPABASE_URL`·`SUPABASE_ANON_KEY`)이 설정돼 있어야**
     동작한다(Actions 탭에서 최근 실행이 성공인지 한 번 확인). 그래도 전날 눈으로 한 번 더 본다.
2. **데이터셋 확정·선택** — 쓸 콘텐츠 한 벌(종목·주가·재무·힌트·시황)이 최종본인지 확인.
   관리자 [데이터셋] 탭에서 **엑셀 양식/화면**으로 만들고([MANUAL_CONTENT](MANUAL_CONTENT.md)), [진행] 탭 드롭다운에서 **쓸 데이터셋을 고른다**(시작 전만 전환 가능).
   개발자 검증이 필요하면 `npm test`(79개)와 `node scripts/verify_game.mjs --yes`(5라운드 실 DB)가 **전부 통과**해야 한다.
3. **관리자 비밀번호 강화** — 현재 개발용 기본값은 약하다(값은 `.env` 참조, 문서엔 안 적는다). 실전용 강한 값으로 **DB와 `.env`(배포 시 Vercel 환경변수)를 동시에** 바꾼다.
   - DB: Supabase SQL Editor에서 `select private.set_admin_secret('새_강한_비밀');` 1회 실행.
   - `.env`: `VITE_ADMIN_PASSWORD`를 같은 값으로. **두 값이 어긋나면 관리자 로그인이 막힌다.**
   - (비밀은 git·마이그레이션에 절대 넣지 않는다.)
4. **게임 리셋** — 관리자 [진행] 탭 → **[게임 리셋]**(RESET 입력). 또는 `reset_game`.
   거래·보유·힌트·속보가 지워지고 R0(시작 전)으로 돌아간다(조·콘텐츠는 유지).
5. **검증용 조 삭제** — `TEST-01`·`TEAM_1~5`(플레이테스트) 등 테스트 조를 [조 관리] 탭에서 삭제.
   **안 지우면 학생 리더보드에 테스트 조가 보인다.**
6. **입장 방식 정하기** — [진행] 탭 **게임 설정**에서 입장 방식을 고른다(시작 전만).
   - **코드 방식** — [조 관리] 탭에서 조를 미리 만들고 참가 코드·시드머니를 정해 **각 조에 코드 배부**.
   - **자율 입장(open)** — 학생이 **닉네임 + 공용 게임 PIN**으로 직접 입장(조를 미리 안 만들어도 됨). 시드머니는 게임 설정의 기본 시드가 적용된다.
     - **[조 관리] 탭 맨 위 "게임 입장 PIN 카드"에서 [PIN 발급]** → 나온 **4자리 PIN을 학생 전원에게 전달**(칠판·화면에 크게). 발급 전엔 입장 불가.
     - 학생은 닉네임을 정해 그 PIN으로 입장하면 실시간으로 [조 관리] 표에 뜬다. 부적절한 닉네임은 표에서 **이름을 눌러 수정**.
   - **시드 변경은 시작(R0) 전에만** 가능하다.
7. **최종 점검** — 학생 화면(`/`)에 테스트 흔적이 없는지, 종목/가격/재무가 맞는지 직접 눈으로 확인.
   교육장 와이파이에서 **배포 주소(https://cufic-wts.vercel.app)** 와 Supabase 접속이 되는지 실기기로 확인.

## B. 당일 진행 순서

> 게임 루프는 GAME_RULES §1과 같다. 관리자는 [진행] 탭에서 조작한다.

> 버튼 정식 명칭·화면 위치는 [MANUAL_ADMIN](MANUAL_ADMIN.md)을 본다. [진행] 탭 상단의 **"다음 할 일"** 카드가 매 단계 눌러야 할 버튼을 안내한다.

1. **입장 확인** — 학생들이 **참가 코드** 또는 **닉네임+PIN(자율 입장)**으로 입장. 관리자 [조 관리]에서 **접속 열(최근 10분 초록)**로 전원 확인.
2. **R1 시작** — **[대회 시작 (ROUND 1 열기)]**로 R1을 연다(0→1, **힌트 없음**). → **[타이머 시작 (설정 시간)]**으로 거래 창을 연다.
   학생 즉시 매매. 설정 시간 뒤 자동 마감. *(길이 조절이 필요하면 진행 중 [+1분]/[−1분].)*
3. **라운드 반복 (R2~)** — 매 라운드:
   - **[다음 연도로 넘어가기 (순위 갱신)]** → 다음 연도 가격 공개 + 순위 변동 + (R2~) **힌트 자동 배분**.
   - **[리더보드]로 순위 변동을 학생에게 보여준다**(큰 글씨 모드, 단독 1위 골드). 힌트 배분 경고가 있으면 확인.
   - **[타이머 시작 (설정 시간)]** → 거래. 마감까지 대기.
   - *필요하면* [진행] 탭에서 **공통 속보** 발송.
4. **최종 라운드 매매까지 끝나면** → **[대회 종료]**.

## C. 종료 절차

1. **[대회 종료]** — `admin_end_game`. 최종 연도(2025) 가격이 공개되고 최종 정산된다.
   전 학생 화면에 **대회 종료 모달**(최종 순위·자산·수익률 + 전체 순위표)이 자동으로 뜬다.
2. **시상/복기** — [리더보드] 큰 글씨 모드로 최종 순위 발표. 힌트·재무를 되짚어 판단 과정 복기.
3. **결과 저장** — [리더보드] 탭 **[대회 결과 내보내기 (CSV)]**로 순위·라운드별 스냅샷·거래 로그를 파일로 받는다(엑셀에서 열림).
4. **뒷정리** — 다음을 위해 데이터를 남길지 정한다. 다시 쓰려면 [게임 리셋]으로 초기화(테스트 흔적 방지).

## D. 알려진 트러블슈팅

- **RPC를 바꿨는데 "함수를 찾을 수 없다"** — PostgREST 스키마 캐시 때문이다. 마이그레이션/함수 변경 후
  REST에 반영되기까지 **약 20초** 걸린다. 잠시 기다렸다 새로고침.
- **관리자 기능이 전부 `unauthorized`** — DB `private.config`의 비밀과 `.env`의 `VITE_ADMIN_PASSWORD`가
  다르거나, 새 DB라 비밀이 아직 설정 안 됨(fail-closed). A-3으로 맞춘다.
- **[타이머 시작]을 눌렀는데 학생이 매매 안 됨** — 라운드가 R0(시작 전)이면 타이머가 안 열린다.
  먼저 [연도 넘기기]로 라운드를 1 이상으로. 또는 이미 마감(`round_ends_at` 지남) → 다시 시작.
- **거래가 갑자기 잠김** — 타이머 만료(정상). 다음 라운드로 넘기거나 타이머를 다시 연다.
  마감 뒤 거래는 서버가 거부(`round_closed`)하므로 콘솔로도 안 뚫린다.
- **시드(seed.sql)만 다시 넣고 싶다** — `db push --include-seed`는 **새 마이그레이션이 없으면 시드를 건너뛴다.**
  Management API로 `supabase/seed.sql`을 직접 실행해야 한다(`SUPABASE_ACCESS_TOKEN` 사용, `.env` 참조).
- **순위가 안 바뀐다** — 정상이다. 라운드 중엔 전 거래가 같은 가격이라 평가금액이 안 변한다.
  순위는 **[연도 넘기기]로 가격이 바뀔 때만** 움직인다.
- **모든 화면이 "fetch failed"/로딩만 반복** — Supabase 프로젝트가 **일시정지**됐을 확률이 높다
  (무료 플랜, 약 1주 무요청). [대시보드](https://supabase.com/dashboard/project/zhwidhvoxcoljffvqhol)에서
  **[Resume project]** → 1~2분 뒤 복구. 재발 방지는 A-1(Keep-Alive 시크릿 설정).
- **세로 화면에 "돌려주세요"만 보임** — 태블릿을 가로로. 세로(1023px↓)는 지원하지 않는다.

## E. 리허설에서 확인할 것 (이 초안의 검증 항목)

- [ ] 데이터셋 선택 → 리셋 → 조 생성/자율 입장 준비 → (코드 방식) 코드 배부까지 걸리는 시간
- [ ] **자율 입장 방식** — 학생 닉네임 입장·PIN 발급·재접속이 실기기에서 매끄러운지
- [ ] R1~R5 + 종료까지 실제 소요 시간(라운드당 10분 기준 약 50분 + 전환)
- [ ] 힌트 자동 배분이 순위대로 맞게 나가는지(꼴찌=S), 등급 부족 경고 처리
- [ ] 다수 조 동시 접속·동시 매매 시 지연/오류
- [ ] 실기기 태블릿 터치·그리기·회전
- [ ] 대회 종료 모달이 전 학생 화면에 뜨는지, 재접속 시에도
- [ ] **[대회 결과 내보내기 CSV]**가 순위·스냅샷·거래를 빠짐없이 담는지
