## 2026-08-20 · 엑셀 제작 양식 정본 하나로 통일 + 자동계산 참조 열 + v3 아카이브

재무제표 개편(입력 7개) 후 양식이 두 계열로 갈렸다: 파서와 맞는 **자동생성물**(코드 buildWorkbook, 색 없음)과
검수자가 만든 **docs/v3**(색칠·풍부한 안내문이 있으나 재무 시트가 옛 5지표라 업로드 시 재무가 깨짐). 정본 하나로 통일.

- **정본 = `docs/CUFIC_WTS_데이터셋_제작양식.xlsx`** (버전 없는 파일명으로 확정) — v3의 재무 시트만 새 7입력으로 갈아끼워 만들었다.
  v3의 좋은 요소(필수=노랑·선택=파랑 색칠, 26줄 읽어주세요 안내, % 가격 입력법, 예시 데이터, 작성 순서·규칙)를 **그대로 보존**하고
  재무 시트만 교체. 파서 검증 통과(오류 0·재무 103행·7입력).
- **자동계산 참조 열(검수자 v4.1)** — 재무 시트에 자산합계·부채합계·자본·영업이익·당기순이익·부채비율·ROE를 **`※자동` 표기 열**로 덧붙였다
  (제작자가 값을 보며 채우게, 회색 표시). 파서는 이 열들을 **'무시됨(info)'으로 건너뛴다** → 입력 7개만 읽으므로 안전(오류 0 재확인).
  **제작자는 `※자동` 열을 채우지 않는다.**
- **왜 XML 교체** — SheetJS 커뮤니티판은 셀 색을 **쓸 수 없다**. 그래서 코드 자동생성물엔 색을 못 넣는다. v3의 색을
  살리려면 파일을 직접 편집하는 수밖에 없어, 재무 시트만 수술했다.
- **관리자 [양식 다운로드] 버튼(buildWorkbook)** 도 읽어주세요를 v3 수준으로 풍부하게 채우고, **재무 시트에 `※자동` 수식 열 7개**(엑셀 수식 + 캐시값)를 넣어 정본과 **구조·헤더 동일**로 맞췄다. 단 셀 색은 없음(SheetJS 한계) → 색이 필요하면 정본 파일 사용.
- **옛 v3 → `docs/archive/`** — 삭제하지 않는다(교보재팀이 이미 v3로 작업 중이라 대조용 필요). 단 **업로드 금지**(재무 깨짐).
- **편의기능(정본 파일 한정)** — 힌트 시트에 **드롭다운(데이터 검증)** 추가: B열 등급=`S,A,B,C,D`, D열 방향=`up,down,flat`(B5:B200·D5:D200, 오타 차단). **틀 고정(머리글 4행)은 이미 있었음**(전 데이터 시트 `pane ySplit=4`). SheetJS는 데이터검증을 못 쓰므로 **zip XML을 직접 수술**(JSZip, sheet5.xml에 `<dataValidations>` 삽입)해 넣었고 색·수식·styles.xml은 무변경 보존. **buildWorkbook(앱 다운로드)엔 드롭다운 없음** — 정본 파일을 재생성하면 드롭다운·색이 날아가니 주의.
- 검수자가 검토 후 교보재팀에 재배포 예정.

## 2026-08-20 · 재무제표 전면 개편 — "5지표 나열" → 실제 2표(입력 7 + 자동계산) (마이그레이션 0031)

교보재팀 확정 요구로, 재무제표를 지표 5개(revenue/op_income/net_income/debt_ratio/roe) 나열에서
**실제 재무제표 2표 구조**로 교체했다. 목업(`docs/재무제표_모달_목업_v4.html`)이 구현 기준.

- **입력은 잎 7개만, 나머지는 계산.** 저장: 유동자산·비유동자산·유동부채·비유동부채 / 매출·영업비용·영업외비용.
  자산합계·부채합계·자본·영업이익·당기순이익·부채비율·ROE는 `src/metrics.js`의 **`deriveFinancials()` 한 곳**에서 계산(저장 안 함).
  - **왜 계산값을 저장하지 않나** — 이중 소스가 되면 어긋난다. 입력만 저장하고 화면·검증·엑셀이 같은 함수로 계산하면 항상 일관.
  - **자본잠식(자본 ≤ 0)** — 부채비율·ROE는 0으로 나눌 수 없어 `null`("—") + 자본잠식 뱃지.
- **학생 모달** — 목업 그대로: 연도 탭(스포일러 유지) → 재무상태표 T자형(자산=부채+자본 항등식 줄) + 손익계산서 단계 차감(비용/적자는 파란 괄호) + 파생 칩(부채비율·ROE, ? 설명) + 용어 접기.
- **관리자 편집·엑셀** — 입력 7개만 받고, 자본·이익·비율은 옆에 실시간 계산 표시. 엑셀 파서는 헤더 이름 매핑(양식 v4는 검수자가 제작 예정, 헤더 이름만 맞으면 됨).
- **기존 103행 데이터 처리** — 라이브 표는 폐기 후 더미로 재적재(교보재팀이 v4 콘텐츠로 대체 예정). 저장된 데이터셋 2개(id 2·10)는
  **삭제하지 않고 payload를 새 구조로 변환**(옛 지표를 역산해 채움 — 매출·영업이익·당기순이익·부채비율·ROE가 그대로 재현되는 일관된 더미). `metrics.js` 지표 정의도 `FIN_INPUTS`/`FIN_DERIVED`로 재작성.
- **검증** — `deriveFinancials` 단위 테스트(항등식·자본잠식) + 브라우저 실측(학생 2표 모달·관리자 실시간 계산) 통과. Vitest 79개.
- **비밀번호/힌트와의 연결** — 힌트·정합성 검증은 재무 값을 읽지 않으므로(가격 방향만) 영향 없음.

## 2026-08-20 · 자율 입장을 공용 게임 PIN으로(팀별 PIN 폐기) + 조 관리 재설계 (마이그레이션 0030)

대회 운영을 **자율 입장(open)**으로 확정하고, 팀마다 다른 PIN을 **게임 하나에 공용 PIN 하나**(Kahoot식)로 바꿨다.
강사가 시작 전 무작위 4자리를 발급(`admin_set_game_pin`)해 학생 전원에게 알려주고, 학생은 **닉네임 + 공용 PIN**으로 입장·재접속한다.

- **왜 공용 PIN** — 팀별 PIN은 조마다 다른 값을 학생이 외워야 하고 강사가 일일이 관리해야 했다. 공용 PIN 하나면
  교실 배부가 간단하다(칠판에 한 번). 대신 닉네임이 조 신원이 되어, 남의 닉네임을 아는 학생이 그 조로 들어갈 수
  있다 — 감독 하 교실에선 수용, `[팀 확인 대기]`로 남김. (재접속 허용 쪽을 택해 기기 교체·새로고침 복구를 쉽게.)
- **왜 `private.config`에 저장** — `game_state`는 anon이 select로 읽는다(학생 화면이 `join_mode`를 거기서 읽음).
  거기 PIN을 두면 학생이 REST로 읽어 게이트를 우회한다. `private`는 PostgREST 노출 경로가 없다(admin_secret과 동일 원리).
  **signals는 공개 테이블이라 PIN 값을 신호 payload에 싣지 않는다**(플래그만).
- **조 관리 재설계** — open 모드에선 강사가 조를 안 만드므로 [+ 조 추가]·코드 열·팀별 PIN 열을 숨기고, 맨 위에
  **게임 입장 PIN 카드**(발급/재발급)를 둔다. 학생이 입장하면 실시간 목록에 추가된다. 부적절 닉네임은 **이름 인라인 수정**(`admin_rename_team`).
- **학생 로그인 단순화** — 옛 3단계(닉네임→발급 PIN 안내→재접속 PIN)를 **한 화면**(닉네임 + 입장 PIN)으로.
- **팀별 `teams.pin` 열은 폐기(미사용)** — 파괴적 drop 없이 방치(스키마 되돌릴 여유 없음). 새 코드에서 부활 금지.
- **검증** — 서버 함수 API 검증(신규·재접속·틀린 PIN·이름 수정·game_pin 반환) + 브라우저 실측(관리자 PIN 카드·학생 한 화면 입장·실시간 목록) 통과.
- **라이브 전환** — `join_mode=open`, TEAM_1~5 삭제, 게임 PIN 발급. ⚠ 배포 사이트는 `main` push 후에야 새 흐름 반영.

## 2026-08-14 · 데이터셋을 엑셀(.xlsx) 양식으로 왕복 — 파싱은 SheetJS

**결정.** 비개발자가 게임 데이터 한 벌을 **엑셀 양식**(시트 6개: 읽어주세요/게임설정/종목/재무제표/힌트/시황)으로
만들고, 관리자 [데이터셋] 탭 **[📊 엑셀 업로드]** → 검증 → **새 데이터셋으로 생성**한다. 각 데이터셋은 같은
양식으로 **[엑셀] 내보내기**해 수정·재업로드할 수 있다. (검토 중 잠깐 만든 CSV(zip) 방식은 폐기 — 엑셀 한
파일이 더 직관적이고 여러 시트를 한 번에 다룬다.)

**파싱 라이브러리 = SheetJS(`xlsx`).**
- *왜 SheetJS:* 순수 JS·무의존성이라 브라우저(Vite) 번들에 깔끔히 들어가고 읽기·쓰기를 모두 한다.
- *왜 npm 등록본이 아니라 공식 CDN tarball(0.20.3):* npm 레지스트리의 `xlsx`는 0.18.5에 고정돼 있고
  알려진 취약점(프로토타입 오염·ReDoS)이 **미패치**다. 유지보수사가 패치본을 자사 CDN으로만 배포하므로
  `https://cdn.sheetjs.com/xlsx-0.20.3/…` tarball로 설치해 패치본을 고정했다.
- *ExcelJS 대신:* ExcelJS는 노드 의존성이 있어 Vite 번들이 번거롭다. SheetJS가 브라우저에 더 맞다.
- *번들 영향 차단:* SheetJS는 ~0.5MB라 `AdminDatasets`에서 **동적 import**로 코드분할 — 학생 번들·관리자
  기본 로드엔 안 들어가고 엑셀 버튼을 누를 때만 받는다.

**검증 이원화.** 구조 문제(필수 시트/열 누락·종목ID 참조 오류·라운드 연도↔가격 열 불일치·숫자 아님)는
**에러(생성 차단)**, 교육 정합성(힌트 방향↔다음 해 등락 불일치·라운드별 등급 커버리지 부족)은 **경고(생성 허용)**.
원천 양식: `docs/CUFIC_WTS_데이터셋_제작양식_v3.xlsx`. *(→ 2026-08-20 정본 v4로 통일, v3는 `docs/archive/`로 이동.)*

## 2026-07-28 · 힌트 자동 배분 — 등급순 × 순위 라운드로빈 (floor 공식 폐기)

등급 구간 매핑(`floor((순위−1)÷조수×5)`)을 버리고, **라운드 힌트 풀을 등급순(S→D, 같은 등급 작성순)으로
꼴찌부터 1위 방향으로 라운드로빈** 배정한다. 힌트가 소진될 때까지 반복 → 전부 지급, 하위권일수록 좋은
힌트 + 더 많은 개수.

- **왜** — 구간 매핑은 등급별 1개 풀을 가정해 "인접 등급 대체" 같은 예외가 필요했고, 남는 힌트가 버려졌다.
  라운드로빈은 풀 개수에 무관하게 전부 나눠주고 하위권 우대가 자연스럽다.
- **순위·타이브레이크** — 평가금액 오름차순(꼴찌 먼저), 동률은 조 생성순 → id. **결정론적**이어야 한다.
- **공용 규칙** — `src/distribute.js`(미리보기·Vitest·SQL이 같은 규칙). `distribute_round_hints`(0025) 재작성.
  시뮬레이션 테스트(`distribute.test.js`): 7조×11힌트 → 꼴찌 S+C … 1위 C.
- **부수 발견·수정** — 관리자 로그인 직후 `refresh()`가 옛 secret 클로저를 써서 조·힌트·재무·시황이
  비어 있던 선존 버그를 `secretRef`로 고쳤다(관리자 데이터가 로그인 즉시 채워짐).

## 2026-07-28 · 콘텐츠를 코드에서 DB로 (B, Phase 1)

- **이행** — Phase 1a: `financials`·`macro` 테이블(0020) + 시드/gen-seed 확장 + 앱이 DB에서 읽기

## 2026-07-24 · 극단 수익 밸런스는 콘텐츠(힌트)로, 코드는 표시만 손댄다

힌트를 완벽히 따르면 매 라운드 몇 배씩 복리로 불어 최종 자산이 수백억(+수만%)까지 간다.
이걸 **규칙(몰빵 한도·가격 변동폭 제한)으로 막지 않기로** 했다.

- **왜** — 극단 수익은 **힌트 설계로 조절할 사안(콘텐츠 영역)** 이다. 코드에 한도·캡을 넣으면 규칙이
  복잡해지고, 데이터·힌트가 확정되면 다시 손봐야 한다. 밸런스는 힌트의 구체성·정확도와 가격
  시나리오로 팀이 맞춘다.
- **코드는 표시만 개선** — 수익률 차트를 **로그 스케일 + 억 단위 + 라운드별 수익률 % 막대**로 바꿔
  지수 성장을 읽히게 한다. 숫자 자체(수백억)는 그대로 둔다.

## 2026-07-24 · 힌트 자동 차등 지급 (R2부터, 하위권 우대)

수동 지급만 있던 등급 힌트를 **라운드 전환 시 자동 배분**으로 바꿨다(강사 수동은 보조로 유지).
`advance_round`가 새 라운드 가격을 공개한 뒤 `distribute_round_hints()`를 호출한다.

- **순위 기준 = 새 가격 공개 직후**(leaderboard와 동일), 직전 라운드 스냅샷이 아니다.
  **왜** — R1은 전 조가 같은 가격에 사서 평가금액이 시드로 **전부 동률**이다. 스냅샷으로 R2를
  배분하면 전원 같은 등급이 된다. 가격이 갈린 뒤라야 "8위=S" 같은 차등이 나온다.
  ("직전 정산 순위"를 이렇게 해석 — **이 해석 자체가 [잠정], 팀 컨펌 대상**)
- **R1 제외** — 첫 배분은 R2 진입 때. R1 진입(0→1)은 지급 없음.
- **매핑 [잠정] (팀 컨펌 대기)** — 등급구간 = `floor((순위−1) ÷ 조수 × 5)`, 상위부터 D→S.
  동률은 `rank()`로 같은 순위=같은 등급. 8조 예: 1~2 D / 3~4 C / 5 B / 6~7 A / 8 S.
- **힌트 풀** — 라운드당 등급별 1개. 그 등급이 없으면 인접 등급(|Δ| 최소)으로 대체하고,
  `advance_round` 응답에 경고를 실어 관리자 화면이 토스트로 알린다.
- **부수** — 배분 후 `hints_changed` 신호 → 학생은 "새 힌트 도착" 토스트로 알게 된다.

## 2026-07-24 · 주문서 일괄 체결 → 즉시 체결 + 라운드 타이머 (작년 방식 복원)

`order_sheets`/`save_order_sheet` 방식을 접고 `place_order`(즉시 체결)를 되살렸다.
매수·매도를 누르면 서버가 그 자리에서 체결한다. 대신 라운드마다 관리자가 [타이머 시작]을
눌러야 거래가 열리고, `round_duration_seconds`(기본 600초=10분) 뒤 자동으로 닫힌다.
아래 "즉시 체결 → 주문서 일괄 체결"(2026-07-17)을 뒤집는다.

- **왜** — 팀 확인 결과 작년 실제 방식이 즉시 체결이었다. 누른 즉시 예수금·보유가 바뀌는
  피드백이 교육적으로 더 직관적이라는 판단. 라운드제와의 정합은 **타이머**가 맡는다 —
  거래 창을 관리자가 열고 닫으니 "라운드 안에서만 매매"라는 성질은 그대로다.
- **게임 루프** — [연도 넘기기](`advance_round`: 새 가격 공개 + 직전 라운드 평가금액 스냅샷 +
  타이머 초기화) → 관리자가 순위 변동 확인 → [타이머 시작](`start_round_timer`) → 학생 즉시 매매 →
  10분 뒤 자동 마감 → 다시 [연도 넘기기].
- **타이머 강제는 서버** — `place_order`가 `now() < round_ends_at`을 검사한다. 학생이 콘솔로
  우회해도 마감 뒤 거래는 거부(`round_closed`). 클라이언트 카운트다운은 표시용일 뿐이라,
  시계가 어긋나도 판정은 서버 시각이 한다.
- **순위 변동 시점** — 라운드 중엔 전 거래가 같은 가격이라 평가금액이 안 변한다. 연도를
  넘겨 가격이 바뀔 때만 순위가 움직인다 — "정산 시점에만 순위가 바뀐다"는 성질은 유지된다.
- **order_sheets는 휴면** — 파괴적 drop 없이 테이블·`save_order_sheet`·`order_funds_ok`를
  남겨뒀다(아무도 호출하지 않음). 그래서 아래 "매도 대금을 매수 자금으로 인정" 잠정 규칙 논의도
  함께 보류된다 — 즉시 체결에선 매수·매도가 각자 현재 예수금에 대해 독립적으로 판정되어 무관해진다.
- **타이머 길이 하드코딩 금지** — 조 수·시드처럼 `round_duration_seconds` 설정값(기본 600).
- **검증** — 임시 5라운드 설정 + 더미 2025·2026 주가로 전 과정 실측 통과(즉시체결·순위 변동·
  타이머 시작 전/만료 게이트 포함), DB는 3라운드로 원상복구. `db push`로 실서비스에 적용됨.
