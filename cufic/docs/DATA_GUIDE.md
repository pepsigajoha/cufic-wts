# 데이터 교체 가이드 (DATA_GUIDE)

> **갱신: 2026-08-20.** 다음 게임을 위해 종목·주가·재무·힌트를 갈아끼우는 방법.
> 비개발자용 "만드는 법"은 [MANUAL_CONTENT.md](MANUAL_CONTENT.md), 이 문서는 **형식·정합성·파일 파이프라인** 참조.

## ⭐ 이제 기본 경로는 "관리자 화면" (코드 불필요)

콘텐츠가 전부 DB로 이관돼(2026-07-28), **관리자 화면만으로 새 게임을 통째로 구성**할 수 있다.
개발자·명령어 없이:

- **종목·가격** 탭 — 종목 추가/수정(소개·업종·상장라운드·연도별 가격)
- **재무·시황** 탭 — 재무제표·거시지표 편집
- **힌트** 탭 — 힌트 작성(잘못된 호재/악재는 "⚠ 등락 불일치" 배지로 경고)
- **진행 → 게임 설정** — 라운드 수·연도·최종연도·시드·타이머 (시작 전에만)
- **진행 → 데이터 점검** — 저장 전 정합성 전체 검사
- **데이터셋** 탭 — 완성한 콘텐츠를 통째로 저장·전환, `.json`으로 백업·공유·인수인계

> **아래 "파일 파이프라인"은 이제 보조 경로다.** 새 DB 초기 템플릿을 만들거나, 대량 데이터를 한 번에
> 넣을 때만 쓴다. 정합성 테스트(Vitest)는 그 **템플릿 검증용**으로 유지한다. 라이브 콘텐츠는 DB가 원천.

## ⭐⭐ 엑셀로 만들기 (비개발자 추천 · 한 판 통째로)

엑셀만 알면 게임 한 판 데이터를 통째로 만들 수 있다. **정본 양식: `docs/CUFIC_WTS_데이터셋_제작양식.xlsx`**
(현재 기본 데이터셋이 예시로 채워져 있고, 필수=노랑·선택=파랑 색칠. 파서와 1:1). 시트 6개 — **읽어주세요**(안내) / **게임설정** / **종목** /
**재무제표**(입력 7개) / **힌트** / **시황**. 헤더에 **"(선택)"**이 붙은 열은 비워도 된다.
*(옛 v3는 `docs/archive/`에 대조용으로 보관 — 재무 시트가 옛 5지표라 업로드하면 안 됨.)*

**순서**
1. 양식을 연다 — 새로 만들려면 `docs/`의 양식을, 기존 걸 고치려면 관리자 [데이터셋] 탭에서 그 데이터셋의
   **[엑셀]** 버튼으로 내려받는다.
2. 시트를 채운다(작성 순서: ① 게임설정 → ② 종목: **가격을 먼저** → ③ 재무제표 → ⑤ 시황 → ④ 힌트).
   - **게임설정**: 항목 이름(A열)은 그대로, 값(B열)만. `R1 연도`… 는 종목 시트의 `YYYY년 가격` 열과 **같아야** 한다.
     - **`타이머(초)`가 실제 라운드 거래 시간**이다(예: 600=10분). [타이머 시작]이 이 값을 그대로 쓰고 진행바 기준도 이 값. 진행 중 ±1분으로 미세 조정.
   - **종목**: 한 행 = 종목 하나. ID는 `S01,S02…`. **업종은 선택**. 상장라운드 = 이 라운드부터 등장.
     가격 칸은 **숫자=가격(원)** / **끝에 %=전년 대비 등락률**(예: `+80%`, `-10%`). 첫 등장 연도는 반드시 가격,
     빈칸/0 = 거래정지·미상장.
   - **재무제표**: 한 행 = 한 종목의 한 해. **입력 7개(억원)**: 유동자산·비유동자산·유동부채·비유동부채·매출·영업비용·영업외비용.
     자산·부채·자본·이익·부채비율·ROE는 자동 계산돼 넣지 않는다. 미상장·폐지 연도는 행을 뺀다. 열은 이름으로 찾으므로 순서가 달라도 된다.
   - **힌트**: R1은 없음, R2부터. **방향·관련종목은 선택** — 채우면 방향(`up`/`down`/`flat`)이 관련 종목의
     다음 해 등락과 맞는지 자동 검증(안 맞으면 경고), 비우면 검증을 건너뛴다(참고 표시). 관련종목은 `S04,S02`처럼 쉼표로.
   - **시황**: 한 행 = 한 해. 한 줄 요약은 학생 시황판 맨 위에 크게 보인다.
3. 관리자 [데이터셋] 탭 → **[📊 엑셀 업로드]** → 파일 선택.
4. **검사 리포트**가 뜬다 —
   - **에러**(빨강): 필수 시트/열 누락, 종목ID 참조 오류, 라운드 연도↔가격 열 불일치, 숫자 아님, 첫 연도에 % → **고쳐서 다시**.
   - **경고**(노랑): 힌트 방향↔등락 불일치, 라운드별 등급 커버리지 부족 → 확인만 하고 진행 가능.
   - **참고**(회색): % 등락률 환산 결과("S02 2021: +80% → 13,140원"), 방향/관련 없어 검증 건너뜀, 모르는 열 무시됨.
5. 에러가 없으면 **이름을 정해 [새 데이터셋으로 생성]**(기존 덮어쓰기 아님). 만든 뒤 [편집]으로 열어 쓴다.

> 엑셀은 UTF-8/CP949 상관없이 열리고, 내보내기는 엑셀에서 바로 열리게 저장된다. 파싱은 SheetJS(→ DECISIONS).

## 파일 파이프라인 (초기 템플릿·대량 입력용, 보조)

> 개발을 몰라도 따라 할 수 있게 적었다. 명령어는 그대로 복사해 실행하면 된다.

## 큰 그림 — 원천은 파일 3개, 나머지는 자동 생성

```
seed_stocks_2025.json      (종목·연도별 주가)   ┐
seed_financials_2025.json  (연도별 재무제표)     ├─▶  node scripts/build-data.mjs  ─▶  src/data.js
scripts/build-data.mjs 안의 DESC·HINTS (소개·힌트) ┘                                        │
                                                                                          ▼
                                                              node scripts/gen-seed.mjs  ─▶  supabase/seed.sql  ─▶  DB
```

- **손으로 고치는 파일은 3곳뿐**: 위 JSON 2개 + `build-data.mjs` 안의 소개(`DESC`)·힌트(`HINTS`).
- `src/data.js`와 `supabase/seed.sql`은 **자동 생성물** — 직접 고치지 말 것(다음 생성 때 덮어써진다).
- 이렇게 하는 이유: 앱 화면·정합성 테스트·DB 시드가 **전부 한 원천**을 보게 해서, 셋이 어긋나지 않게.

## 1. 데이터 파일 형식

### `seed_stocks_2025.json` — 종목과 주가
```json
{
  "round_year_map": { "1": 2020, "2": 2021, "3": 2022, "4": 2023, "5": 2024 },
  "final_year": 2025,
  "total_rounds": 5,
  "stocks": [
    {
      "id": "S01",                 // 종목 코드(고유). 화면·힌트 related가 이걸 가리킨다
      "name": "승주보험",           // 종목명(중복 불가)
      "description": "",           // (미사용 — 소개는 build-data.mjs의 DESC에서)
      "listed_from_round": 1,      // 이 라운드부터 상장(그 전엔 목록에 안 보임). 보통 1
      "prices": {                  // 연도 → 가격(원, 정수). round_year_map의 모든 연도 + final_year
        "2020": 29300, "2021": 35000, "2022": 50200,
        "2023": 53000, "2024": 52600, "2025": 33000
      },
      "display_order": 1           // 목록 정렬 순서
    }
  ]
}
```
- **필수 필드**: `id`, `name`, `listed_from_round`, `prices`, `display_order`.
- **가격 규칙**: `round_year_map`의 모든 연도 + `final_year`에 값이 있어야 한다.
  값이 **0**이거나 비면 그 해는 **거래정지(상장폐지)** — 매수·매도 차단, 평가액 0.
- **라운드 수를 바꾸려면** `round_year_map`·`total_rounds`·`final_year`를 함께 고친다.

### `seed_financials_2025.json` — 재무제표 (v4: 입력 잎 7개)

**입력하는 값은 7개뿐**이고, 자산합계·부채합계·자본·영업이익·당기순이익·부채비율·ROE는 **화면에서 자동 계산**된다(저장 안 함).
계산식은 `src/metrics.js`의 `deriveFinancials`가 유일한 소스:
`자산=유동+비유동자산 · 부채=유동+비유동부채 · 자본=자산−부채 · 영업이익=매출−영업비용 · 당기순이익=영업이익−영업외비용 · 부채비율=부채÷자본×100 · ROE=당기순이익÷자본×100`.
자본 ≤ 0(자본잠식)이면 부채비율·ROE는 화면에서 `—`.

```json
{
  "units": {
    "current_assets": "억원", "noncurrent_assets": "억원",
    "current_liabilities": "억원", "noncurrent_liabilities": "억원",
    "revenue": "억원", "operating_expense": "억원", "nonoperating_expense": "억원"
  },
  "financials": {
    "S01": {
      "2020": { "current_assets": 27529, "noncurrent_assets": 27529, "current_liabilities": 10729, "noncurrent_liabilities": 16094, "revenue": 38000, "operating_expense": 34800, "nonoperating_expense": 800 },
      "2025": null                 // 미상장/상장폐지 연도는 null → 화면에서 '-'
    }
  }
}
```
- 종목 코드(`S01`)별로, **주가에 나온 모든 연도**(`final_year` 포함)의 입력 7개가 있어야 한다.
- 상장 전/폐지 후 연도는 `null`로 둔다(입력 7개 전부 채우거나, 아예 null — 일부만 채우면 안 됨).
- 입력 7개: 유동자산(`current_assets`)·비유동자산(`noncurrent_assets`)·유동부채(`current_liabilities`)·비유동부채(`noncurrent_liabilities`)·매출(`revenue`)·영업비용(`operating_expense`)·영업외비용(`nonoperating_expense`). 전부 억원, 음수 넣지 않는다.

### `scripts/build-data.mjs` 안의 소개·힌트 (콘텐츠)
- **`DESC`** — 종목 코드 → 한 줄 소개. 예: `S01: '자동차·생명 보험을 파는 회사예요…'`
- **`HINTS`** — 등급 힌트 배열. 한 개 예시:
  ```js
  { round: 2, grade: 'S', impact: 'up', headline: "D게임즈 신작, 사전예약 서버 마비…", related: ['S04'] }
  ```
  - `round` — 그 힌트가 **뜨는** 라운드(그 해→**다음 해** 등락을 예고). **R1(round:1)은 없음.**
  - `grade` — `S`/`A`/`B`/`C`/`D`. **라운드마다 등급별로 1개**씩 있어야 자동 배분이 매끄럽다.
  - `impact` — `up`(호재)/`down`(악재)/`flat`(중립). **다음 해 실제 등락과 일치해야 한다**(아래 §3).
  - `related` — 근거가 되는 종목 코드 배열. 시장 전반 힌트는 `[]` + `flat`.
  - `headline` — 학생에게 보이는 문구. **호재/악재라고 대놓고 쓰지 않는다**(학생이 판단).

## 2. 교체 절차

> 사전: 프로젝트 폴더에서 터미널(PowerShell)을 연다. `.env`가 세팅돼 있어야 DB 적용이 된다.

1. **JSON 2개를 새 데이터로 고친다** (§1 형식대로). 필요하면 `build-data.mjs`의 `DESC`·`HINTS`도.
2. **`src/data.js` 생성**:
   ```bash
   node scripts/build-data.mjs
   ```
   끝에 `data.js 생성 — 종목 N, 힌트 M, 라운드 5 …`가 뜨면 성공.
3. **정합성 테스트 통과 확인** (아래 §3이 자동 검사):
   ```bash
   npm test
   ```
   **빨간 실패가 하나라도 있으면 데이터가 어긋난 것** — 고칠 때까지 진행하지 않는다.
4. **`supabase/seed.sql` 생성**:
   ```bash
   node scripts/gen-seed.mjs
   ```
5. **DB에 적용** — 시드만 다시 넣는 것이라 마이그레이션과 경로가 다르다.
   `db push --include-seed`는 새 마이그레이션이 없으면 시드를 **건너뛴다**. 그래서 시드는
   **Management API로 `supabase/seed.sql`을 직접 실행**한다(방법은 [OPERATIONS.md](OPERATIONS.md) 참조).
6. **리셋 + 검증**:
   ```bash
   node scripts/verify_game.mjs --yes     # 5라운드 풀 시뮬(실 DB, reset 포함 — 대회 중 금지)
   ```
   그 뒤 브라우저로 학생·관리자 화면을 직접 눌러 확인한다(빌드 통과만으로 "된다"고 하지 않는다).

## 3. 정합성 규칙 (어기면 테스트가 막는다)

`src/data.test.js`가 아래를 전수 검사한다. **이게 학생을 지키는 안전장치다.**

- **힌트 방향 = 실제 등락.** `impact: 'up'`인 힌트의 `related` 종목은 **그 라운드 연도→다음 해**에
  실제로 올라야 한다(`down`은 내려야). *어긋나면 정직하게 판단한 학생이 손해를 본다.* R5 힌트는
  다음 해가 `final_year`(2025)다.
- **종목 코드·이름 중복 없음**, 모든 종목에 소개 1줄.
- **`related`의 종목이 실존**(오타·삭제된 코드 없음).
- **가격은 0 이상 정수.** `listed_from_round` 그 해엔 가격이 0보다 커야 한다(상장인데 거래정지면 모순).
- **재무는 연도별로 null이거나 입력 7개가 빠짐없이 숫자.** 자산·부채·비용 입력은 음수 불가(적자는 영업비용>매출로 표현). 자동 계산(`deriveFinancials`)은 별도 단위 테스트로 검증(항등식·자본잠식).
- **라운드는 1씩·연도도 1씩 증가**, `final_year`는 마지막 라운드 다음 해.

### 개념 정리 (헷갈리기 쉬움)
| 용어 | 뜻 | 화면 |
|---|---|---|
| `listed_from_round` | **신규상장** — 그 전엔 목록에 아예 없음(상장 예정) | 종목이 안 보이다가 그 라운드에 나타남 |
| 가격 0 | **상장폐지/거래정지** — 목록엔 있으나 거래 불가·평가액 0 | "거래정지" 태그, 매매 버튼 잠김 |
| `final_year` | 대회 종료 시 최종 정산에 쓰는 연도(매매 없음) | [대회 종료] 후 이 가격으로 순위 확정 |

## 4. 자주 하는 실수

- **`src/data.js`를 직접 고침** → 다음 `build-data.mjs` 실행에 덮어써진다. JSON을 고쳐야 한다.
- **주가엔 있는데 재무엔 없는 연도**(또는 그 반대) → 테스트가 "재무 열이 없다"로 막는다.
- **힌트 방향을 실제 등락과 반대로 씀** → "호재·악재 태그가 다음 해 실제 등락과 일치한다" 테스트 실패.
- **시드 생성만 하고 DB 적용을 안 함** → 화면은 옛 데이터. `gen-seed` 뒤 반드시 DB에 넣는다(§2-5).
- **대회 중 `verify_game.mjs` 실행** → `reset_game`이 껴 있어 실데이터가 날아간다. 절대 금지.
