# 게임 규칙서 (GAME_RULES)

> **갱신: 2026-08-15** · 게임 모델 **v3**(즉시 체결 + 라운드 타이머).
> 확정된 규칙과 아직 미확정인 규칙을 구분해 적는다. 미확정은 `[팀 확인 대기]`로 표시한다.
> *왜* 이렇게 정했는지는 [DECISIONS.md](DECISIONS.md), *운영 절차*는 [OPERATIONS.md](OPERATIONS.md).
> 코드가 원천이다 — 이 문서는 `place_order`·`advance_round`·`start_round_timer`·`admin_end_game`·
> `distribute_round_hints`·`join_team`·`leaderboard`(supabase/migrations)와 `src/distribute.js`·`src/App.jsx`를 따라 쓴다.

CUFIC WTS는 청소년 교육용 **라운드제 모의투자**다. 학생이 조를 이뤄 참가하고, 강사가 라운드(연도)를
넘기면 주가가 바뀌며 손익이 난다. 재무제표와 힌트를 근거로 **판단하는 법**을 가르치는 게 목적이다.

## 1. 게임 모델 — 즉시 체결 + 라운드 타이머

- **즉시 체결.** 학생이 [매수]/[매도]를 누르면 서버(`place_order`)가 **그 자리에서** 체결한다.
  예수금·보유가 즉시 반영된다. 옛 "주문서 일괄 체결" 방식은 폐기됐다(→ §12).
- **거래는 타이머가 열린 동안만.** 관리자가 **[타이머 시작]**을 눌러야 거래가 열린다.
  기본 **10분**(`round_duration_seconds`=600초, 하드코딩 아님) 뒤 자동 마감된다. 관리자는
  진행 중 **±1분**으로 늘리거나 줄일 수 있다(`adjust_round_timer`, 줄여도 최소 now()+10초는 남긴다).
- **타이머 강제는 서버.** `place_order`가 `now() < round_ends_at`을 검사한다. 마감 뒤엔 콘솔로도
  못 뚫는다(`round_closed`). 화면 카운트다운은 표시용일 뿐, 판정은 서버 시각이 한다.
- **가격 0 = 거래정지.** 매수·매도 차단, 평가액 0. (상장폐지의 표현 → §7)

### 게임 루프 (관리자 조작)
```
데이터셋 선택 ─▶ [대회 시작] (ROUND 1 열기)
      │            └─ R1은 전 조 같은 시드 → 평가금액 전원 동률. 힌트 없음
      ▼
[타이머 시작] ─▶ 거래 창 열림(기본 10분) ─▶ 학생 즉시 매매 ─▶ 시간 종료 시 자동 마감
      ▼
[다음 연도로 넘어가기] ─▶ 다음 해 가격 공개 + 직전 라운드 평가금액 스냅샷 + 힌트 자동 배분(R2~)
      │                     └─ 보유가 재평가돼 순위가 바뀐다
      ▼
관리자가 순위 변동 확인 ─▶ 다시 [타이머 시작] …  (마지막 라운드까지 반복)
      ▼
[대회 종료] ─▶ 최종 정산 연도 가격 공개 + 최종 평가금액 스냅샷 + 전 학생 종료 모달
```

- 라운드 진행 순서는 **가격 공개(연도 넘기기) → 순위 확인 → 타이머 시작 → 마감**이다. 라운드 사이
  타이머가 꺼진 구간(가격은 공개됐지만 거래는 잠긴 상태)에서 관리자가 순위 변동을 확인한다.

### 순위 · 리더보드

- **순위는 [연도 넘기기]로 가격이 바뀔 때만 움직인다.** 라운드 중엔 전 거래가 같은 가격이라
  평가금액이 안 변한다 — **거래별 실시간 순위 갱신은 없다.** 순위는 [연도 넘기기](또는 [대회 종료])가
  새 가격을 공개하는 순간에만 재계산된다.
- **순위 기준 = 평가금액(절대 금액) 내림차순**(`leaderboard`). 동률은 **같은 순위 숫자**로 묶이되,
  표시 순서는 **조 생성순(created_at)**으로 고정한다(결정론적).
- **단독 1위만 골드로 강조.** 공동 1위(동률)면 아무도 강조하지 않는다(`AdminBoard`의 `soleFirst`).
- 리더보드는 **직전 라운드 스냅샷과 비교해 순위 등락(▲▼)**을 함께 보여준다.

## 2. 라운드 구성 — 데이터셋마다 가변

- **라운드 수·연도·종목 수·힌트 수는 데이터셋(시나리오 팩)이 정한다. 하드코딩은 없다.**
  총 라운드는 `total_rounds`, 각 라운드→연도는 `round_year_map`, 최종 정산 연도는 `final_year`.
  관리자가 게임 시작 전 데이터셋을 고르면 그 구성으로 진행된다 — **규칙은 구성과 무관하게 동일하다.**
- **최종 정산 연도는 매매하지 않는다.** [대회 종료](`admin_end_game`)가 `current_round`를
  `total_rounds+1`로 올리면 `current_price`가 `round_year_map`에 없는 라운드를 `final_year`로
  폴백해 전 계산이 그 연도 가격으로 잡힌다. 종료 시 **떠나는 라운드**와 **최종 연도** 두 지점을
  모두 스냅샷한다(수익률 차트에서 마지막 해가 빠지지 않게).

**현재 기본 데이터셋(예시 · 값은 초안)**

| 라운드 | 연도 | 비고 |
|---|---|---|
| R1 | 2020 | 시작. 전 조 같은 시드 → 평가금액 전원 동률. **힌트 없음** |
| R2 | 2021 | 첫 자동 힌트 배분 |
| R3 | 2022 | (신규상장 종목이 이 라운드부터 노출되는 식) |
| R4 | 2023 | |
| R5 | 2024 | 마지막 매매 라운드 |
| — | **2025** | `final_year`. **매매 없음.** [대회 종료]가 이 가격으로 최종 정산 |

> 위 5라운드(2020~2024)+최종(2025)는 **현재 데이터의 값일 뿐**이다. 다른 데이터셋은 라운드 수·연도가
> 다를 수 있다. 표가 아니라 §1·§2의 규칙이 확정 사항이다.

- **원금(시드).** 기본값 `default_seed`(예: 1억). 관리자가 화면에서 설정한다(하드코딩 아님).
  - **⚠ 순위 전제 — 전 조 시드를 같게 준다.** 현재 리더보드·힌트 배분 순위는 **평가금액(절대 금액)**
    기준이라, 시드가 같아야 공정하다(시드 같으면 금액 순 = 수익률 순). **시드를 조마다 다르게 주려면
    순위 기준을 수익률(pnl_pct)로 바꿔야 한다**(`leaderboard`·`distribute_round_hints` 수정 필요, 미적용).
- **금액은 원 단위 정수(bigint).** 평균단가만 numeric. 부동소수점 금지.

## 3. 입장 방식 — 코드 / 자율 입장

관리자가 게임 설정에서 `join_mode`를 고른다(`admin_update_game_config`, 시작 전에만 변경 가능). 기본은 `code`.

- **코드 입장(`code`).** 강사가 미리 만든 **참가 코드**로 조가 로그인한다. 코드는 조 격리의 핵심이라
  노출되면 안 된다(→ CLAUDE.md의 RLS/RPC 규칙).
- **자율 입장(`open`, `join_team`).** 학생이 **닉네임 + 공용 게임 PIN**으로 직접 조를 만든다(Kahoot식).
  - **공용 게임 PIN은 게임 하나에 하나.** 강사가 시작 전 무작위 4자리로 발급(`admin_set_game_pin`)해 학생 전원에게
    알려준다. `private.config('game_pin')`에 저장 — `game_state`는 anon이 읽으므로 거기 두면 학생이 우회한다.
  - 닉네임 **2~12자**. 같은 닉네임(대소문자 무시)이 있으면 **재접속**으로 처리(공용 PIN 확인).
  - **새 조 생성은 시작 전(R0)에만.** 게임이 시작(`current_round≥1`)되면 새 조는 못 만든다(`join_closed`).
  - **재접속(닉네임+공용 PIN)은 진행 중에도 허용.** 기기를 바꾸거나 새로고침해도 다시 들어올 수 있다.
  - PIN 미발급이면 입장 자체가 막힌다(`no_game_pin`). 강사가 조 관리 화면에서 발급/재발급하고 값을 읽어 전달한다.
  - 같은 기기는 localStorage에 저장된 코드로 자동 재접속(PIN 불필요).
  - **트레이드오프:** 공용 PIN이라 닉네임이 조 신원이다. 감독 하 교실에선 낮지만, 남의 닉네임을 아는 학생이
    그 조로 들어갈 수 있다(`[팀 확인 대기]`로 남기되 현재는 수용).

## 4. 힌트 시스템

- **등급 S / A / B / C / D.** S가 최상위(가장 좋은 힌트). 조마다 **받는 힌트가 다르다.**
- **R1 무지급.** 첫 배분은 **R2 진입** 때부터(`distribute_round_hints`는 `p_hint_round < 2`면 아무것도 안 준다).
- **R2부터 순위 기반 자동 배분 — 라운드로빈(꼴찌부터, 하위권 우대).**
  [연도 넘기기](`advance_round`)가 새 가격을 공개한 **직후 순위**로 `distribute_round_hints()`를 자동 호출한다.
- **수동 지급은 보조.** 관리자가 특정 조에 특정 힌트를 추가로 줄 수 있다. 지급 안 된 힌트는
  어떤 경로로도 학생에게 안 보인다.
- **호재/악재는 화면에 표시하지 않는다.** 호재인지 악재인지는 **학생이 판단**한다(교육 목적).
  DB `impact` 태그(`'up' | 'down' | 'flat'`)는 **내부 정합성 검증**용이다 — 태그는 관련 종목의
  **다음 해 실제 등락과 일치**해야 한다(`src/data.test.js`). 어긋나면 정직하게 판단한 학생이 손해를 본다.

### 배분 방식 — 등급순 × 순위 라운드로빈

`src/distribute.js`가 미리보기·테스트·SQL이 공유하는 단일 규칙이다.

1. **힌트 풀 정렬** — 그 라운드 힌트를 **등급 좋은 순(S→D)**, 같은 등급은 **작성순(id 오름차순)**으로 줄 세운다.
2. **팀 정렬(꼴찌 먼저)** — **평가금액 오름차순**(꼴찌=낮은 평가금액), 동률은 **생성순(created_at) → id**로 결정론적.
3. **라운드로빈** — 정렬된 힌트를 **꼴찌부터 1위 방향**으로 한 장씩 배정하고(`hn % 조수`), **힌트가 소진될 때까지** 반복.
4. **결과** — 힌트를 **전부 지급**, 하위권일수록 **좋은 힌트 + 더 많은 개수**. (등급 부족·인접 대체 개념 없음.)

- **순위 기준 = 새 가격 공개 직후 평가금액.** R1은 전 조 동률이라 배분 안 함(R2부터).
- 배분 후 `hints_changed` 신호 → 학생은 "새 힌트 도착" 토스트로 인지.
- 관리자 힌트 탭의 **[자동 배분 미리보기]**가 조별로 **받을 힌트(등급·개수)**를 표로 보여준다
  (현재 순위 기준, 연도를 넘기면 달라질 수 있음).
- **예 (7조 × 11힌트, 풀 S1·A2·B2·C3·D3)** — 꼴찌 = **S + C**(2장) … 1위 = **C**(1장). (`src/distribute.test.js`로 고정.)
  힌트 수·조 수가 다른 데이터셋에선 배분 결과도 달라진다 — 규칙만 동일하다.

## 5. 공통 속보 (broadcasts)

- 강사가 **전체 조에 동시에** 보내는 한 줄 알림. 힌트(조별 차등)와 별개다.
- 학생 화면 헤더의 종 아이콘 → 팝업(최신순). 전원 공개(격리 없음).
- 관리자 진행 탭에서 발송/회수. 발송 시 `broadcast` 실시간 신호.

## 6. 시황판 (거시경제 지표)

- 헤더 **[📈 시황]** 버튼 → 라운드(연도)별 **기준금리·GDP성장률·실업률·환율·물가상승률·국제유가**를 표로 보여준다.
- 학생이 **재무제표·힌트와 함께 판단하는 '배경'**이다. **방식 A(표시형)** — 지표가 가격을 직접
  움직이진 않고, 데이터를 가격 스토리에 맞게 저작한다(예: 금리 인상 → 성장주 조정).
- **현재 라운드 연도까지만 공개**(미래 스포일러 차단, 재무제표와 동일).
- 데이터는 `scripts/build-data.mjs`의 `MACRO`(연도별 지표 + 한 줄 시황) → `src/data.js` → DB `macro` 테이블.
- `[팀 확인 대기]` — 값은 초안(2020 코로나 → 2021 유동성 → 2022 인플레·금리인상 스토리).
  **인과 엔진(방식 B, 지표가 주가를 자동으로 움직이는 것)은 향후 과제 — 현재 미적용.**

## 7. 상장폐지 / 신규상장 (다른 상태)

- **신규상장(`listed_from_round`)** — 그 라운드 전에는 종목 목록에 **아예 안 보인다**(상장 예정).
  해당 라운드부터 노출·거래 가능.
- **상장폐지 = 가격 0.** 목록엔 남되 "거래정지" 태그, 매수·매도 차단, 평가액 0(전액 손실).
- 둘은 다르다. 서버는 가격 0으로 이미 매매를 막으므로, `listed_from_round`는 **표시상 신규/기존 구분**이다.
- **0으로 나누는 코드를 만들지 않는다**(가격 0 종목의 수익률·비중 계산 주의).

## 8. 파산 위기

- **자산(평가금액)이 원금의 20% 이하**로 쪼그라들면 학생 화면에 **파산 위기 안내 배너**가 뜬다
  (`App.jsx`: `started && !ended && seed > 0 && equity <= seed * 0.2`).
- 문구는 **격려**다 — "힌트와 재무제표를 다시 보고 신중히 골라봐요, 아직 기회는 있어요".
- **게임에서 퇴출하지 않는다.** 계속 매매할 수 있다. 표시상의 경고일 뿐이다.

## 9. 색상 규칙 (한국 증시 관례)

모든 색상은 **CSS 변수**로만 쓴다(하드코딩 금지). 다크·라이트 두 테마에서 동일한 의미를 유지한다.

| 의미 | 변수 | 색 |
|---|---|---|
| 상승 · 매수 | `--up` | 빨강 |
| 하락 · 매도 | `--down` | 파랑 |
| 강조(단독 1위 등) | `--gold` | 골드 |
| 접속 표시 | (green) | 초록 |
| 보합 · 거래정지 · 중립 | `--muted` | 중립 회색 |

## 10. 밸런스 결정 — 몰빵 제한 없음

- **한 종목에 전액을 넣는 것(몰빵)도, 가격 변동폭도 제한하지 않는다.**
- 힌트를 완벽히 따르면 매 라운드 복리로 불어 최종 자산이 수백억(+수만%)까지 갈 수 있다.
  이걸 **규칙(코드)으로 막지 않는다.**
- *왜* — 극단 수익은 **힌트 설계(콘텐츠)로 조절**할 사안이다. 코드에 한도·캡을 넣으면 규칙이
  복잡해지고 데이터가 바뀔 때마다 다시 손봐야 한다. 밸런스는 힌트의 구체성·정확도와 가격 시나리오로 맞춘다.
- **코드는 표시만 개선** — 수익률 차트를 로그 스케일 + 억 단위 + 라운드별 % 막대로 바꿔 지수 성장을
  읽히게 했다. 숫자 자체는 그대로 둔다.

## 12. 소멸한 규칙 (기록)

- **매도 대금을 매수 자금으로 인정하는 규칙 — 소멸.** 옛 "주문서 일괄 체결" 시절, 한 주문서 안에서
  매도 먼저→매수로 매도 대금을 매수에 쓰는 잠정 규칙이 있었다(작년 시트 수식). **즉시 체결로 전환하며
  무관해졌다** — 매수·매도가 각자 **현재 예수금**에 대해 독립적으로 판정된다. 관련 함수 `order_funds_ok`,
  테이블 `order_sheets`, 함수 `save_order_sheet`·`get_my_order_sheet`는 모두 **0016에서 삭제**됐다.
- **뉴스(전체 공개) → 등급제 힌트.** 초기 `news` 테이블(is_published 전체 공개)은 조별 차등 지급이
  안 돼 `hints`/`hint_grants` 체계로 대체됐다(0005, `news` drop).
- **힌트 등급 구간 매핑(floor 공식) → 라운드로빈.** `floor((순위−1) ÷ 조수 × 5)`로 등급 구간을 나누던
  방식은 폐기됐다(0025). 현재는 등급순 × 순위 라운드로빈(§4).
